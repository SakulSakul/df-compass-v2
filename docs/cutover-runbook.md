# 컷오버 실행 런북 (2026-08-05 — 심의 확정분, 발효 대기)

> 발효 스위치 = CG-2·CG-3 결과 회신 → 감리자 발효 판정 → **공지 발송**.

## 1. CG-2 — 배포 secrets 확인 [사용자, Streamlit Cloud 콘솔]
대상 앱: df-compass-v22 (v2). Settings → Secrets 에서 확인·회신:
- [ ] `GEMINI_API_KEY` 있음/없음 (없으면 앱 기동 불가 — 필수)
- [ ] `ANTHROPIC_API_KEY` 있음/없음
  - 없음 + 수용 시: critical 의미확장층(LLM 분류기)이 fail-open — keyword
    floor(`_CRITICAL_FLOOR` + DB 키워드 2층)는 유지됨. 절단 시 Claude 폴백
    불가 → 게이트 재합성이 구제 경로 (R3 라이브 실측 1건 구제 확인).
- [ ] 확인 후 3층 체크리스트: ① 소스 = v2 main 최신 커밋 ② Streamlit 재빌드
  반영 ③ 기동 로그 `[registry] ledger built: docs=101 … docs_with_articles=97`
  (정화 원장 숫자 — 98 이면 구코드) + 비critical/critical/negative 3문항 +
  안전 표면(배너·4단·핫라인·강등 칩) 육안.

## 2. CG-3 — v1 기동 리허설 [사용자, 브라우저]
- v1 앱(df-nexus-ai) 접속 → 기동 성공 여부 / 화면 렌더 정상 / 질문 1건 답변
  생성 확인. 결과("성공/실패·렌더·답변 생성")를 감리자에게 회신.
- 목적: 롤백 착지점 실존 확인 (v1 폐기 API 리스크의 실측 검증).

## 4. 롤백 규약 (30일 창)
**신호 4종 (1인 관측 가능형)** — 하나라도 발생 시 롤백:
1. 위조 비강등 실사례 (비실재 인용이 강등 없이 표출된 실제 답변)
2. critical 안전 표면 미표출 (배너/4단/핫라인 누락 실사례)
3. v2 기동 실패 (재부팅으로 미복구)
4. 임직원 품질 신고 2건 (동일 계열)

**복귀 절차**: ① v1 앱 Sharing 재공개 ② 공지 정정 발송 ③ v2 비공개 전환
④ OBSERVATION 에 신호·시각 기록 ⑤ 전면 재심의 소집.
ADR-8 개정(질의 로그 영속화) 전까지 신호 관측은 사람 관측형만 —
브라우저 확인·임직원 회신이 소스다.
