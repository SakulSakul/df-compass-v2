## 단계 1~3 — 승인 후 일괄 구현
계층별 기능 플래그 필수(재검증 실패 시 어블레이션용). wave 별 커밋 분리.

**wave 1 계측**: embed/RPC/rerank/neighbors/synth 단계 타이머 + 하니스
산출물에 최종 청크 수·합성 입력 토큰·라우터 히트 여부 기록. 이것 없이는
재검증이 성립하지 않는다.

**wave 2 (비검색 계층)**:
- 앵커 사전: 원장 SELECT 로 문서별 인용 가능 앵커 집합 파생(조문형 vs
  C-class 76건). 합성과 verify 가 동일 사전 공유.
- 합성 계약: 조문형 문서는 투입 청크에 실재하는 조번호만 인용(발명·추론
  금지), C-class 는 조번호 표기 금지·문서명+섹션 제목 인용, 인용 형식
  스키마 고정(라벨 있으면 표기 의무).
- verify 확장: 문서명 실재 검증 추가. pass/degrade/block 판정 로직은
  1비트도 변경 금지.
- conf: 연속값 폐기 → 서수 4등급 HIGH(원문 앵커 ok) / MEDIUM 상한(프록시
  포함 시) / LOW(강등 발생) / UNVERIFIED(앵커 0 — 0.0 으로 뭉개지 않음).
  앵커 수는 포화 반영만(선형 가중 금지). [⓪-2(i) 판명: conf 는 표시·기록
  전용 → 본 항 정지 조건 미해당, 진행]

**wave 3 (검색 계층)**:
- doc_router+force_include: 질의→지배문서 라우팅, 라우팅 청크를 리랭크 풀
  주입 + 최종 top_k 예약석 1~2석(컷 면제). 라우터 저확신 시 no-op —
  add-only 불변식. 홀드아웃 표현의 라우터 사전·프롬프트 수록 금지.
- 예산: rerank_pool 15→25, top_k 3→5, neighbors ±2→±1, 중복 제거 후 총
  청크 상한 8.
- 프록시: 명단 상수(CREDO·징계기준 + ⓪-3 발견분=없음), 리랭크 감점, 최종
  top_k 내 프록시 ≤1. 원장 등재 유지. 원문 확보는 비차단 병행.

**재검증**: 동일 하니스 재러닝 + 위조 8건 재주입 + 라우터 단위 테스트 +
홀드아웃 구어체 3문항(신규 작성·라우터 사전 비수록·재러닝 전 봉인 제출).
통과 기준(사전 고정·사후 완화 금지): B+A' 7건 전건 회수 / D 5건 ≥4 /
기존 통과 38쌍 신규 미스 0 / neg 6/6 / 위조 비강등 유출 0 / "프록시
포함인데 HIGH" 0건 / 홀드아웃 3문항 회수 / p50 ≤ 23.3s(최종 청크 수 병기,
p95 기록만) / 라우터 정확도 ≥90%. 결과 JSON·로그 커밋 — 독립 감리는
감리자 수행.

**정지 조건**(발생 즉시 중단·보고): 위조 비강등 ≥1 / 라우터 정확도 <90% /
홀드아웃 0 회수 / 청크≤8 인데 p50>23.3s / 프록시 쿼터로 기존 38쌍 신규
미스 / conf=action 판명 상태에서 degrade 급증. 자체 판단 수정 금지 —
전부 심의 복귀 사안.

**상시 금지**: v1 수정 / DB 쓰기 / 키 채팅 / 검증 없는 완료 선언 / 범위 밖
"김에 개선".
